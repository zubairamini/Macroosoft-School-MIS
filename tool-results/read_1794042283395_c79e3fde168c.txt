     1→// ─────────────────────────────────────────────────────────────────────────────
     2→// مکتب‌یار (MaktabYar) — School Management Information System for Afghanistan
     3→// Prisma schema — Phase 1 (vertical slice)
     4→//
     5→// PORTABILITY NOTE (PostgreSQL migration path):
     6→//   This sandbox runs SQLite. Production targets PostgreSQL. Because SQLite
     7→//   has no native enums, enum-like fields are String columns validated by
     8→//   zod schemas at the application boundary (src/server/*/dto.ts). Allowed
     9→//   values are documented per field. On PostgreSQL these become enums.
    10→//
    11→// DATE/TIME INVARIANTS:
    12→//   - Instants (login, audit, created/updated) → DateTime, stored UTC.
    13→//   - Date-only values (birth dates, attendance dates, enrollment dates,
    14→//     academic-year boundaries) → String "YYYY-MM-DD" (ISO date-only).
    15→//     No time component ⇒ no timezone shift can alter birthdays. Convert to
    16→//     `date` column type on PostgreSQL.
    17→//
    18→// MONEY INVARIANT (Phase 3 modules will rely on it):
    19→//   - All monetary amounts are integers in minor units (diram; 100 diram = 1
    20→//     AFN). Binary floating point is never used for money.
    21→//
    22→// CONCURRENCY INVARIANTS:
    23→//   - Optimistic concurrency via `version Int` on editable aggregates
    24→//     (Application, Student, Organization). Bumping is done in transactions.
    25→//   - Scarce/monetary resources (Phase 3: invoices, payments, book copies)
    26→//     will additionally use transactions + row-level checks.
    27→//
    28→// HISTORICAL RECORD INVARIANT:
    29→//   - No soft deletes on financial or academic history. Corrections are new
    30→//     records (reversals / corrections) that reference the original.
    31→// ─────────────────────────────────────────────────────────────────────────────

   540→/// Weekly class schedule. Weekday: 0=شنبه .. 6=جمعه (Afghan week starts
   541→/// Saturday). Period: 1..8 (0 is reserved for whole-day attendance and is
   542→/// rejected here). Non-null columns keep the UNIQUE constraints airtight on
   543→/// SQLite (NULLs would be treated as distinct).
   544→model TimetableSlot {
   545→  id             String   @id @default(cuid())
   546→  classSectionId String
   547→  classSection   ClassSection @relation(fields: [classSectionId], references: [id])
   548→  weekday        Int // 0..6 (شنبه..جمعه)
   549→  period         Int // 1..8
   550→  subjectId      String?
   551→  subject        Subject?    @relation(fields: [subjectId], references: [id])
   552→  staffId        String?
   553→  staff          StaffMember? @relation(fields: [staffId], references: [id])
   554→  roomName       String?
   555→  createdById    String?
   556→  createdAt      DateTime @default(now())
   557→  updatedAt      DateTime @updatedAt
   558→
   559→  // INVARIANTS: a section has at most one slot per (weekday, period);
   560→  // a teacher is in at most one place per (weekday, period).
   561→  @@unique([classSectionId, weekday, period])
   562→  @@unique([staffId, weekday, period])
   563→  @@index([classSectionId])
   564→  @@index([staffId])
   565→}

   567→/// Attendance session for one section on one date.
   568→/// period: 0 = whole-day session (ثبت روزانه), 1..8 = specific class period.
   569→/// "Unrecorded ≠ present": only SUBMITTED sessions count in statistics, and
   570→/// a student without a record row inside a submitted session is counted as
   571→/// «نا-ثبت» (not recorded) — never silently as present or absent.
   572→model AttendanceSession {
   573→  id             String   @id @default(cuid())
   574→  classSectionId String

   625→/// Assessment (quiz / assignment / midterm / final / project) for one
