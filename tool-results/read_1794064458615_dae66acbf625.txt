     3→     3→// Prisma schema — Phase 1 (vertical slice)
     4→     4→//
     5→     5→// PORTABILITY NOTE (PostgreSQL migration path):
     6→     6→//   This sandbox runs SQLite. Production targets PostgreSQL. Because SQLite
     7→     7→//   has no native enums, enum-like fields are String columns validated by
     8→     8→//   zod schemas at the application boundary (src/server/*/dto.ts). Allowed
     9→     9→//   values are documented per field. On PostgreSQL these become enums.
    10→    10→//
    11→    11→// DATE/TIME INVARIANTS:
    12→    12→//   - Instants (login, audit, created/updated) → DateTime, stored UTC.
    13→    13→//   - Date-only values (birth dates, attendance dates, enrollment dates,
    14→    14→//     academic-year boundaries) → String "YYYY-MM-DD" (ISO date-only).
    15→    15→//     No time component ⇒ no timezone shift can alter birthdays. Convert to
    16→    16→//     `date` column type on PostgreSQL.
    17→    17→//
    18→    18→// MONEY INVARIANT (Phase 3 modules will rely on it):
    19→    19→//   - All monetary amounts are integers in minor units (diram; 100 diram = 1
    20→    20→//     AFN). Binary floating point is never used for money.
    21→    21→//
    22→    22→// CONCURRENCY INVARIANTS:
    23→    23→//   - Optimistic concurrency via `version Int` on editable aggregates
    24→    24→//     (Application, Student, Organization). Bumping is done in transactions.
    25→    25→//   - Scarce/monetary resources (Phase 3: invoices, payments, book copies)
    26→    26→//     will additionally use transactions + row-level checks.
    27→    27→//
    28→    28→// HISTORICAL RECORD INVARIANT:
    29→    29→//   - No soft deletes on financial or academic history. Corrections are new
    30→    30→//     records (reversals / corrections) that reference the original.
    31→    31→// ─────────────────────────────────────────────────────────────────────────────
